## Origins

In August 1985 IBM and Microsoft signed a **Joint Development Agreement**. The two companies had already shipped one operating system together — PC-DOS, for the 1981 Personal Computer — and DOS had done its job so well that it was now the problem. It was a real-mode program in a 640 KB room, on machines whose processors had grown up around it: the 80286 could address 16 megabytes and keep programs out of each other's memory, and DOS could not ask it to. OS/2 was the replacement, announced in April 1987 alongside the PS/2 line and shipped that December.

Version 1.0 had no graphics at all — protected memory, preemptive multitasking, and a text screen. The face arrived a year later. **Presentation Manager**, in OS/2 1.1 of October 1988, was the graphical shell and API the two companies had agreed would be the future of the PC: overlapping windows, a device-independent graphics layer, and a programming model that Microsoft would also carry into Windows. Version 1.2 followed in 1989 with **HPFS**, a file system with 255-character names, per-file extended attributes and volumes to 64 GB, at a time when FAT still meant `PROGRAM1.EXE`.

**OS/2 1.3 shipped on 30 November 1990** — Standard Edition first, Extended Edition on the last day of the year, with the 1.30.1 and 1.30.2 refreshes running through 1991. It was a tuning release and a good one: the memory floor came down from 2.5 MB to 2 MB, the print subsystem was rebuilt, **REXX** arrived as the system scripting language in both editions, and **Adobe Type Manager** shipped in the box with a core font set, so the screen and the printer finally agreed with each other. Extended Edition added the things a corporate site bought OS/2 for: Communications Manager, Database Manager, LAN Requester.

It was also the last release built under the Joint Development Agreement. Microsoft shipped its own **OS/2 1.30.1** — codenamed Tiger, bundled with LAN Manager, distinguished mainly by a new SCSI driver architecture called LADDR — and that is the version running on this station, which is why the banner on the screen says *Microsoft* and *1991*. By then Windows 3.0 had been out since May 1990 and had sold in numbers OS/2 never approached. The partnership ended acrimoniously; IBM took OS/2 and rebuilt it 32-bit as **2.0**, Microsoft took the Presentation Manager lessons into Windows and NT, and the two products spent the next decade competing.

## Significance

OS/2 1.3 is the fork in the road, frozen at the moment before it split. Everything the PC industry argued about for the next ten years is already in the box: preemptive multitasking against Windows 3.0's cooperative model, protected memory against a 640 KB free-for-all, a structured graphics API against a DOS program writing to video RAM. On the technical merits 1.3 wins nearly all of those arguments, and it lost the market anyway.

The reason is the **286**. OS/2 1.x is a 16-bit system built for a processor whose protected mode addresses memory in 64 KB segments and offers no way back to real mode without resetting the chip. That made DOS compatibility a single "penalty box" session rather than something OS/2 could be casual about, and it made every application a port rather than a recompile. IBM had insisted on the 286 because it had sold a great many of them; by 1990 the 386 had been on sale for five years, Windows 3.0 was using it, and the constraint OS/2 had been designed around had become the thing holding it back. OS/2 2.0 lifted all of it in 1992 — full 32-bit, multiple DOS sessions, the Workplace Shell — but by then the audience had gone.

What makes 1.3 worth an exhibit rather than a footnote is that it is the first version of OS/2 anyone actually enjoyed running. 1.0 had no desktop, 1.1 was slow and needed memory nobody had, and 1.3 is the one that fits in 2 MB, boots in a reasonable time on a 386, and puts a shell in front of you that looks and behaves like the mainstream PC desktop of 1990 — because it is the design Windows 3.0 shipped six months earlier, from the same drawing board.

## What you're looking at

An i486-class PC of 1990 vintage: **16 MB of memory** (all OS/2 1.x can see), an ISA machine with **VGA** at 640x480 in 16 colours, a **PS/2 mouse** on the i8042 — OS/2 1.3 ships that driver in the base system — and an IDE disk under 504 MB, which is the size a BIOS of the period could address by CHS. There is no USB, no network card and nothing beyond the machine: the exhibit's reach ends at the emulated hardware.

The shell is called the **Desktop Manager**, not the Program Manager. It is the same idea — groups of program icons in windows you open from a list — and the family resemblance to Windows 3.0 is not a coincidence but a shared origin. Underneath it, unlike Windows 3.0, the scheduler is preemptive: a program that stops responding does not take the screen down with it.

The demonstration here opens **Utilities → OS/2 Command Prompt** and types `ver` and `dir`. That is deliberately plain, and it is the point. The command prompt is an OS/2 prompt, not DOS — it is a full protected-mode session running as one task among several, with the Desktop Manager still live behind it, which in 1990 on a PC was the thing worth showing someone.

The pointer is a **relative PS/2 mouse**, the same kind the original hardware had; move it the way you would move a mouse on a desk. Reset restores the machine to the golden state above, so whatever you open belongs to your visit.

## Legacy

OS/2 outlived the partnership by a long way — **Warp 4**, two exhibits along, is IBM's 1996 answer, with the object-oriented Workplace Shell and the slogan about being a better DOS than DOS and a better Windows than Windows. It is the other end of the road that starts here. **Windows 3.11** and **Windows NT 3.51** are the other branch: NT in particular was begun by a team Microsoft hired from DEC while the OS/2 agreement was still running, and was originally meant to be *OS/2 3.0* before Windows 3.0's success rewrote its brief into Windows.

So the screen in front of you is the last common ancestor. The preemptive kernel, the protected memory, the structured graphics API, the idea that a personal computer should be a real operating system and not a program loader — all of it survives, on the other side of the split, in the system most people are reading this on. What did not survive was the name, and the company that kept it.
