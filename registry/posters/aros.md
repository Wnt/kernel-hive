## Origins

The AROS Research Operating System began in 1995, when Amiga owners faced an uncertain future after Commodore’s collapse. Its developers set out to reproduce the documented AmigaOS 3.1 programming interface in an open, portable implementation. The name is a recursive one: the project began as the "Amiga Research Operating System" and later dropped the Amiga to avoid the trademark. The project could not distribute Commodore’s Kickstart ROM or source code, so compatible behavior had to be written independently.

AROS gradually expanded from an API reimplementation into a complete operating system with its own kernel, drivers, libraries, command shell, and graphical environment. It has run on several processor families, though the PC-compatible i386 build remains one of its most approachable forms. Wanderer, its default desktop, takes the role held by Workbench while allowing the project to evolve beyond exact visual reproduction.

## Significance

AROS preserves a distinctive branch of operating-system design. AmigaOS used pre-emptive multitasking, shared libraries, message ports, lightweight processes, assignable paths, and an always-present RAM disk in ways unlike mainstream Windows or Unix systems. Recreating those conventions makes old source code and user habits available without requiring original ROM licenses or aging hardware.

Compatibility is necessarily uneven because applications often relied on undocumented behavior or direct access to Amiga hardware. The project went so far as to write a free, open-source replacement for the Kickstart ROM itself, so AROS can boot a genuine Amiga in place of Commodore’s silicon. The project’s value therefore lies not only in binary fidelity, but in keeping the design space alive and modifiable. It is preservation through continued engineering.

## What you're looking at

The Wanderer desktop presents familiar Workbench-like volumes, a RAM Disk, and the orange-accented visual identity of a modern AROS distribution.

## Legacy

AROS has outlived several commercial attempts to revive Amiga computing. It supplies code to related projects, offers a bridge for developers interested in Amiga APIs, and demonstrates how a community can reconstruct a platform around published behavior. Beside the Amiga 500 exhibit, it forms a useful pair: one preserves the original 1980s system, while the other shows its concepts continuing as open software. The project’s mascot is a cat named Kitty, adopted in 2002 — the kind of detail only a community this old accumulates.
