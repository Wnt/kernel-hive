# Research report: Using agentic coding tools to build high-quality three.js/WebGL scenes

## Key findings

**1. The screenshot feedback loop is the single highest-leverage practice — and it is now officially canon.**
Anthropic's own Claude Code best-practices guide codifies the exact loop: give Claude a visual mock → implement → screenshot the result → compare and iterate, noting that "2-3 iterations produce a good match" and that Claude "performs best when it has clear targets" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices), [rosmur summary](https://rosmur.github.io/claudecode-best-practices/)). Concrete implementations exist: Playwright MCP with Claude Code ([Builder.io guide](https://www.builder.io/blog/playwright-mcp-server-claude-code)), and a leaner pattern — a screenshot harness in the test suite plus a custom slash command that makes the agent visually inspect every captured frame before human review ("catches a significant number of visual issues before I even start reviewing", [Tal Rotbart, Feb 2026](https://medium.com/@rotbart/giving-claude-code-eyes-round-trip-screenshot-testing-ce52f7dcc563)). Nobody credible reports getting good 3D visuals from a blind agent.

**2. The "modality gap" is the documented core limitation — plan around it, don't fight it.**
Jon Radoff's essay ([When AI Learns to Paint, Mar 2026](https://meditations.metavert.io/p/when-ai-learns-to-paint-threejs-and)) is the best experience report: agents are excellent at structure (scene wiring, systems, refactors) but aesthetic fine-tuning through text is lossy and slow — "adjustments a skilled graphics engineer would make in seconds by tweaking a number" take whole agent round-trips. An IJCAI 2025 survey cited there confirms LLMs lack genuine spatial/mental-rotation ability. The practical consequence: **the agent should build the machinery and expose tunable parameters (leva/lil-gui panels); the human does the final aesthetic dial-turning, then the agent persists the chosen values into code.** Needle Inspector explicitly supports this direction — AI applies hand-made inspector edits back to source ([needle.tools](https://needle.tools/needle-inspector-devtools-for-threejs)).

**3. Why LLM scenes look bad is well understood, and the fix is asset-first + constraints, not better prompting.**
A SIGGRAPH Asia 2025 study of MCP-Unity found users asking for complex real scenes exposed "a fundamental mismatch: while MCP-Unity excels at tool orchestration and primitive geometric manipulation, it cannot perform complex operations" ([ACM](https://dl.acm.org/doi/10.1145/3757376.3771417)). Every serious research system converges on the same architecture: the LLM never authors geometry — it **retrieves pre-made assets and places them under explicit spatial constraints solved by an optimizer**. Holodeck (GPT-4 plans layout, populates with Objaverse assets, constraint optimizer arranges them — [holodeck](https://yueyang1996.github.io/holodeck/)); SceneCraft (LLM writes Blender code against a spatial relation graph translated to numerical constraints — [paper](https://www.emergentmind.com/papers/2403.01248)); and constraint-expressive intermediate representations ([arXiv 2507.18625](https://arxiv.org/pdf/2507.18625)). For your gallery: the agent should place glTF assets from a manifest with scale/alignment/clearance rules, not freehand `<boxGeometry>` JSX. That's precisely the difference between the current "beginner's first scene" and a professional one.

**4. Curated skills packs measurably raise agent output quality and are the fastest win.**
The ecosystem matured fast in 2025–26. [majidmanzarpour/threejs-game-skills](https://github.com/majidmanzarpour/threejs-game-skills) (1.1k stars) is the state of the art: a director skill orchestrating specialists (AAA-graphics-builder, debug-profiler, QA-release), with a **"visual scorecard with calibration anchors," Playwright screenshot baselines, render-budget metrics, and canvas pixel verification** — i.e., it operationalizes findings 1 and 3. [emalorenzo/three-agent-skills](https://github.com/emalorenzo/three-agent-skills) gives 100+ pure-three.js rules and 60+ R3F/Poimandres rules (installable via `npx`, works with Claude Code and Codex). These also counter API-churn hallucination (agents defaulting to r128-era idioms when you're on three 0.185 / R3F 9).

**5. Scene-graph MCP tools give agents structured state, not just pixels.**
[threejs-devtools-mcp](https://github.com/DmitriyGolub/threejs-devtools-mcp) (MIT, 59 tools, WebSocket bridge, zero code changes, works with R3F) lets the agent inspect/modify objects, materials, lights and read performance/memory diagnostics live. [Needle Inspector](https://needle.tools/needle-inspector-devtools-for-threejs) is the polished commercial option (scene hierarchy, TSL/shader drill-down, memory-leak detection, MCP server via `npx needle-cloud start`, GLB export; five-star reviews Dec 2025–Jan 2026). Pixels tell the agent *what's wrong*; the scene graph tells it *which node to fix*. Use both.

**6. Blender MCP is hyped; the evidence for it is thin — headless Blender scripts are the developer-shaped alternative.**
[ahujasid/blender-mcp](https://github.com/ahujasid/blender-mcp) has ~22k stars, but a Blender Artists thread soliciting real experiences produced **zero hands-on success stories, only skepticism** ([Sept 2025 thread](https://blenderartists.org/t/blender-and-mcp-your-opinion-experience/1611801)); third-party assays score it 49/100 security, 48/100 reliability ([assay.tools](https://assay.tools/packages/blender-mcp)). Its genuinely useful part is asset integrations (Poly Haven, Sketchfab, Hyper3D Rodin). For a developer, the more robust pattern is the agent writing **committed, reviewable `blender --background --python` scripts that export glTF** — deterministic, diff-able, CI-able ([one-liner example](https://github.com/jakelazaroff/til/blob/main/blender/export-a-blender-file-to-glb-from-the-command-line.md), [Khronos exporter](https://github.com/KhronosGroup/glTF-Blender-IO)). Use it only where kitbashing/baking is actually needed.

**7. Vibe-coded three.js successes prove speed, not visual quality; the community consensus is sober.**
fly.pieter.com went from "make a 3D flying game in the browser" in Cursor to playable in ~3 hours and a claimed $1M ARR in 17 days ([levels.io](https://levels.io/fly-pieter-com-vibecoded-flight-simulator)) — but it looks like programmer art, and [404 Media's counterpoint](https://www.404media.co/this-game-created-by-ai-vibe-coding-makes-50-000-a-month-yours-probably-wont/) is in the title. The 2025 Vibe Coding Game Jam shipped 1,170 browser games (three.js recommended, Mr.doob judging — [jam.pieter.com](https://jam.pieter.com/)). The three.js forum's April 2026 verdict: AI has commoditized "portfolio-style" surface visuals, but one member who got a commercial app "about 95% done" found "the code was irreparable"; performance, WebGPU/WGSL, and architecture still need real depth ([forum thread](https://discourse.threejs.org/t/is-ai-taking-over-the-visual-portfolio-side-of-three-js-what-domains-still-need-real-3d-engineering/91159)). Takeaway: keep architecture human-owned, prompt sequentially, never accept a giant one-shot rewrite.

**8. AI 3D asset generation is now good enough for props; CC0 libraries are good enough for everything.**
Meshy 6 (7 export formats incl. GLB), Tripo (quad retopo in ~2s), Hunyuan3D 2.1 (open-source, image→textured GLB) are all production-viable for background props in 2026, and MCP servers let agents drive them directly ([State of AI 3D 2026](https://www.3daistudio.com/state-of-ai-3d-generation-2026)). For stylistic coherence, though, a single curated CC0 pack family beats mixed AI generations: [Kenney](https://kenney.nl/assets/category:3D) (40k+ CC0 assets, consistent style) and [poly.pizza](https://poly.pizza/bundles) (low-poly glTF packs). Midjourney's role is 2D: `--sref` style references keep concept boards and in-scene poster/signage art coherent ([sref guide](https://sider.ai/blog/ai-tools/how-to-use-midjourney-reference-images-to-build-a-consistent-aesthetic)).

## Recommended agentic workflow for the Kernel Hive rebuild

**Phase 0 — Art direction before any code (human + Midjourney, ~an evening).**
The root cause of "beginner's first scene" is the absence of a target. Produce: (a) 3–6 Midjourney reference boards of the gallery concept (e.g., dark museum hall, spotlit CRT alcoves, per-era wings), locked with `--sref` for consistency; (b) an `ART-DIRECTION.md` in-repo: palette, materials list, lighting plan (key/fill/practicals), camera height and FOV, and **real-world scale rules in meters** (exhibit plinth 0.9m, ceiling 3.5m, walkway ≥2m). Agents follow written constraints far better than taste. This is the reference-image-driven prompting the Anthropic loop expects ([best practices](https://code.claude.com/docs/en/best-practices)).

**Phase 1 — Tooling install (one session).**
- Install [three-agent-skills](https://github.com/emalorenzo/three-agent-skills) (r3f-best-practices + three-best-practices) and cherry-pick the visual-scorecard/QA ideas from [threejs-game-skills](https://github.com/majidmanzarpour/threejs-game-skills); pin three 0.185 / R3F 9 idioms in CLAUDE.md.
- Wire [threejs-devtools-mcp](https://github.com/DmitriyGolub/threejs-devtools-mcp) (or Needle Inspector Pro) against the Vite dev server.
- Build a deterministic screenshot harness: 6–10 named camera bookmarks reachable via URL param (`?shot=atrium`), fixed DPR, wait-for-assets-loaded, driven by Playwright (you already have a Playwright e2e suite in `tests/e2e-live/` to extend). Screenshot the canvas element (or `preserveDrawingBuffer`/post-render `toDataURL`). Commit baseline images.

**Phase 2 — Asset-first scene rebuild.**
- Replace primitive-soup geometry with glTF assets from ONE style-coherent source (poly.pizza/Kenney pack, plus Meshy/Tripo for museum-specific props like CRT monitors and plinths; Poly Haven for HDRI + PBR textures).
- Have the agent generate a **declarative scene manifest** (JSON: asset id, transform, exhibit binding) plus a small validator (no interpenetration, grid alignment, walkway clearance) — the Holodeck/SceneCraft constraint pattern scaled down. The 30 WebCodecs stream textures simply become materials on properly modeled CRT/monitor assets.
- Every agent task = one small change + screenshot loop against the Phase 0 reference board. Sequential, never one giant "make it beautiful" prompt.

**Phase 3 — Lighting and polish (hybrid loop).**
Agent sets up the machinery: environment lighting (drei `Environment` + HDRI), baked/accumulative shadows, restrained postprocessing (bloom, vignette, SSAO), and **leva panels for every tunable**. Human tunes visually; agent reads final values and hardcodes them. This is the direct mitigation of the modality gap (finding 2).

**Phase 4 — Verification gate.**
Screenshot baselines in CI-style checks; perf budget assertions via the devtools MCP (draw calls, triangles, texture memory — you already carry 30 live video textures, so budget headroom is tight); mobile spot-checks. "Looks done" claims require an actual rendered frame, mirroring your lab's existing framebuffer-verification rule.

## Pitfalls to avoid

- **Primitive soup.** Letting the agent freehand box/cylinder JSX is the documented #1 quality killer (MCP-Unity study, Holodeck rationale). Assets + manifest + constraints, always.
- **The one-shot "make it professional" prompt.** Produces the 95%-then-irreparable outcome. Small sequential tasks, each verified by screenshot, architecture decisions human-owned.
- **Trusting "it looks good now" without a frame.** Agents will confidently report visual success blind. Every visual task ends with a rendered screenshot the agent actually reads — same discipline as your lab's framebuffer rule. Beware WebGL canvas capture gotchas (`preserveDrawingBuffer` or post-render capture).
- **Text-tuning aesthetics.** Slowest possible loop (Radoff). Agent builds leva panels; human turns dials; agent persists values.
- **Blender MCP as centerpiece.** Weak real-world evidence; for a developer, committed headless Blender scripts (or skipping Blender entirely via ready glTF assets) are more reproducible.
- **Stale API idioms.** Without pinned skills/CLAUDE.md rules, agents emit r128-era three.js and CDN-script patterns; you're on three 0.185/R3F 9 — say so explicitly and install the best-practices skills.
- **MCP tool bloat.** A 59-tool scene MCP plus Playwright plus skills can crowd context; load only what the phase needs.
- **Ignoring the perf budget.** 30 concurrent WebCodecs video textures is already a heavy baseline; new lighting/postprocessing must be budgeted (draw calls, texture memory) and mobile-tested — AI-generated scenes routinely fail on low-end devices ([MindStudio](https://www.mindstudio.ai/blog/animated-3d-websites-claude-code-ai-video-generation)).
- **Asset license drift.** Prefer CC0 (Kenney, poly.pizza, Poly Haven); Sketchfab pulls via MCP integrations carry per-model licenses.

Bottom line: the hype ("prompt → beautiful world") is false, but the boring version genuinely works in 2026 — reference boards first, curated skills, asset-first assembly under written constraints, a deterministic screenshot loop the agent must pass, and a human on the final aesthetic dials.
