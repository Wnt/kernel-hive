# Texturing the WebGL Computer Museum: PBR Sourcing, AI Generation, and Delivery (researched July 2026)

## Headline reality-checks (things that changed recently)

- **Quixel Megascans is no longer free.** Megascans moved exclusively to Fab; it was free for everyone only until end of 2024, and is paid since 2025. Anything you grabbed before the cutoff keeps its original license forever ([CG Channel](https://www.cgchannel.com/2024/10/epic-games-has-made-megascans-free-to-all-but-only-until-the-end-of-2024/), [80.lv](https://80.lv/articles/megascans-no-longer-free-after-2024)). Fab's Standard License permits use in commercial projects with any engine (three.js included) but forbids redistributing assets as standalone downloads ([Fab EULA](https://www.fab.com/eula)) — relevant because a web app technically serves the texture files to browsers; extracted raw textures at full resolution are a gray area, KTX2-compressed in-app use is normal practice.
- **Quixel Mixer is discontinued** (announced Feb 2026). The final offline build (Mixer 2023.1) is a free download with 800+ bundled assets and runs indefinitely, but is frozen ([CG Channel](https://www.cgchannel.com/2026/02/quixel-mixer-has-been-discontinued-get-the-final-version-for-free/), [quixel.com/products/mixer](https://quixel.com/products/mixer)).
- **withpoly.com is dead as a texture tool.** It 301-redirects to poly.app, which has pivoted to an "AI cloud file browser" — no texture generation at all (verified by fetching both domains directly).
- **Ponzu (ponzu.gg) appears abandoned** — TLS certificate is broken on both apex and www as of July 2026 (direct fetch fails); treat as dead despite AI-directory listings claiming otherwise.
- **Substance 3D Painter 2026 exists as a Steam perpetual license at €194.99/$199.99** (one-time; feature updates until March 2027, keep forever after) — but the Substance 3D Assets library and generative AI features are subscription-only ([Steam page](https://store.steampowered.com/app/4329260/Substance_3D_Painter_2026/), [Adobe community](https://community.adobe.com/questions-59/will-substance-3d-painter-2026-have-a-perpetual-steam-license-629946)). The Texturing subscription (Painter+Designer+Sampler+Assets) rose to $24.99/mo / $249.88/yr in March 2025 ([CG Channel](https://www.cgchannel.com/2025/02/adobe-to-raise-the-price-of-substance-3d-subscriptions/)).

## Recommended pipeline for this project

Given: a developer (not texture artist) driving Claude Code/Codex, existing Midjourney sub, react-three-fiber app, ~15 hero models + environment. The key insight from all research: **do not generate what you can download.** CC0 libraries cover 100% of the environment and most base materials; AI fills the gaps (badges, labels, specific aged-plastic albedos); agents can automate everything except aesthetic judgment.

### Phase 1 — Environment materials: download, don't generate (fully agent-automatable)

1. Pull environment PBR sets (polished concrete / parquet floor, painted plaster walls, brushed + galvanized metal for shelves, dark glass) from **ambientCG** and **Poly Haven** — both CC0, no attribution, unlimited commercial/web use, full map sets (color/normal/roughness/AO/displacement) at 1K–8K ([Poly Haven](https://polyhaven.com/textures), [ambientCG docs](https://docs.ambientcg.com/api/)).
2. **Both have public JSON APIs an agent can script**: ambientCG's API supports search + download by code ([docs.ambientcg.com/api](https://docs.ambientcg.com/api/)); Poly Haven's is at api.polyhaven.com with a published swagger ([polyhaven.com/our-api](https://polyhaven.com/our-api)). Note Poly Haven asks commercial *API integrations* to arrange sponsorship — one-off scripted downloads of CC0 assets for your own app are not that; the assets themselves stay CC0.
3. Also grab a **Poly Haven indoor HDRI** for image-based lighting — this alone (as `scene.environment` / drei `<Environment>`) is the single biggest visual upgrade available, since the current scene has *no* environment reflections and PBR roughness/metalness maps are nearly invisible without an env map.
4. Supplementary CC0 sources: [cgbookcase](https://www.cgbookcase.com/learn/how-to-use-pbr-textures-in-blender) and AMD's **MaterialX library** at matlib.gpuopen.com (290+ materials, Apache 2.0/CC0/MIT, no registration — includes flooring/tiles/metals) ([CG Channel](https://www.cgchannel.com/2021/12/get-290-free-materialx-materials-from-amds-online-library/)).

### Phase 2 — Custom albedos via Midjourney, PBR maps via extraction (mostly automatable)

For surfaces no library has (specific yellowed-ABS gradients, speaker grilles, badge/label sheets, CRT phosphor patterns):

1. Generate albedo in **Midjourney with `--tile`** for tileables ("aged beige computer plastic, fine pebble texture, subtle yellowing gradient, photographed flat, diffuse lighting --tile"). Caveats: `--tile` works on V1–V3/V5-era params (check current model support; it historically skipped V4/Niji), and **upscaling breaks the seam** — take the un-upscaled tile ([Midjourney docs](https://docs.midjourney.com/hc/en-us/articles/32197978340109-Tile), [Aituts guide](https://aituts.com/midjourney-tile/)). Prompt for *flat, evenly-lit, shadow-free* surfaces — baked-in lighting is the classic failure mode of AI albedos.
2. Extract normal/height/AO/roughness from that albedo. Ranked for an **agent-driven headless pipeline**:
   - **DeepBump** — free (GPL), ML normal+height from a single image, runs as a Blender add-on **and a plain Python CLI** (ONNX Runtime, documented in cli.md) — the best fit for scripted batch extraction ([GitHub](https://github.com/HugoTini/DeepBump), [project page](https://hugotini.github.io/deepbump)).
   - **Materialize** (Bounding Box Software) — free/GPL, purpose-built photo→full PBR set with tiling tools, and supports **XML clipboard-command automation**; Windows-only, Unity-based, unmaintained since ~2018 but works ([boundingboxsoftware.com](https://www.boundingboxsoftware.com/materialize/), [CG Channel](https://www.cgchannel.com/2018/10/free-tool-materialize-converts-photos-to-pbr-materials/)).
   - **Adobe Substance 3D Sampler** "Image to Material (AI Powered)" — best quality per user reports: ML delights shadows out of albedo, category-specific models (plastic/wood/ground…), auto-tiling; GUI-driven, subscription-gated ($24.99/mo Texturing plan or $199.99 Steam perpetual) ([Adobe docs](https://experienceleague.adobe.com/en/docs/substance-3d-sampler/using/filters/tools/image-to-material), [surfacementor writeup](https://surfacementor.com/2025/10/10/%F0%9F%A4%96-using-ai-powered-image-to-material-in-adobe-substance-3d-sampler/)).
   - **NormalMap-Online** — alive, free, browser-based, normal/displacement/AO/specular from heightmap; fine for one-offs, not automation ([cpetry.github.io](https://cpetry.github.io/NormalMap-Online/), verified live).
   - **InstaMAT** — the serious Substance alternative: free **Pioneer license** for <$100k revenue (full Studio, commercial use with credit), and an **InstaMAT Pipeline CLI** that executes material graphs headlessly — but Pipeline is *excluded* from the free tier (Indie perpetual $489) ([pricing](https://instamaterial.com/de/licensing/), [Pipeline docs](https://docs.instamat.io/Products/InstaMAT_Pipeline)).
   - Skip: AwesomeBump (stale), ArmorLab (officially "preview with many rough edges", paid binaries, merged into armortools repo) ([armorlab manual](https://armorlab.org/manual), [GitHub](https://github.com/armory3d/armorlab)).
   - Roughness caveat: single-image roughness inference is the weakest map from all these tools; for flat plastics it's often better to author roughness as a near-uniform value + wear mask than trust extraction.

### Phase 3 — Texturing the 15 hero models (the judgment-heavy part)

Two viable routes; recommend A with B as accelerator:

**Route A — Blender procedural materials, scripted by agents, baked to maps (recommended).** Blender is free, fully Python-scriptable (`bpy` node graphs), and runs headless (`blender --background --python bake.py`). An agent can literally write the "aged beige plastic" material as a node graph (noise-driven yellowing gradient + AO-masked grime + edge-wear via bevel/pointiness masks), apply per-model tweaks, and bake BaseColor/Normal/ORM per object — reproducibly, in CI. Community references: [batch lightmap-bake script for three.js](https://discourse.threejs.org/t/made-a-blender-script-for-batch-baking-lightmaps-to-optimize-models-for-threejs/82346), [headless AO bake gist](https://gist.github.com/AndrewRayCode/760c4634a77551827de41ed67585064b), [procedural-bake how-to](https://reflectorange.net/en/archives/how-to-bake-textures-in-blender-03.html). This is the only route where "agent does it headlessly" is fully true.

**Route B — Substance Painter smart materials.** No off-the-shelf "aged beige retro computer" smart material surfaced in research, but close bases exist to retint: "Dirty & Old Plastic" packs, 50-material packs including "Green Old Plastic" / "Post-Apoc Microwave Oven", industrial packs with light/heavy wear variants on Gumroad/ArtStation ([search summary](https://kutaycengil.gumroad.com/l/substancesmartmaterials), [CG-Ammo mix](https://cg-ammo.gumroad.com/l/jKmMP)). Painter's mesh-map-driven edge wear/dirt generators are exactly the "aged plastic" look — but it's GUI work, a real (if modest) learning curve for a dev, and €194.99 (Steam perpetual, no Assets library). Good for the 3–4 hero-est models; overkill for all 15.

**Route C — AI mesh texturing (reality-checked).** **Meshy's Texture (retexture) mode** accepts *your* uploaded mesh and emits albedo/normal/roughness/metallic (+AO), up to 4K; free tier 100 credits/mo (CC-BY output), Pro $20/mo (private, ~1000 credits; texture-only ≈10–15 credits/job, API on paid) ([Meshy docs](https://docs.meshy.ai/en/webapp/guides/3d-model/ai-texturing), [pricing](https://docs.meshy.ai/en/webapp/pricing)). Reviews: PBR maps "technically correct and convincing" on hard-surface objects, but auto-UVs can be messy on complex meshes ([Unite.AI review](https://www.unite.ai/meshy-ai-review/)). **StableProjectorz** (free, now AGPL open-source, Windows+NVIDIA) projects SD/ControlNet output onto meshes with multi-view consistency — powerful, interactive-only ([stableprojectorz.com](https://stableprojectorz.com/), [GitHub](https://github.com/IgorAherne/StableProjectorz)). **Hunyuan3D-Paint 2.1** (Tencent, open weights, June 2025) is the state of the art in *self-hostable* PBR texture synthesis for existing meshes — albedo+metallic+roughness, multi-view-consistent — but needs ~21 GB VRAM for texturing ([GitHub](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1)); only viable if labhost gains a big GPU. For precise period-accurate machines (SE/30, C64…), AI mesh texturing tends toward "plausible generic" — use it for drafts, not finals. **DreamTextures** (free Blender add-on, still maintained with Blender 4.1+ builds) does SD texture generation + "Project Dream Texture" inside Blender ([GitHub releases](https://github.com/carson-katri/dream-textures/releases), [CG Channel on free AI add-ons](https://www.cgchannel.com/2023/02/these-free-ai-add-ons-create-pbr-materials-inside-blender/)).

### Phase 4 — UV + baking automation

- **UV unwrap:** Blender Smart UV Project via `bpy` is fine for hard-surface boxes (most retro computers are boxes). **xatlas** is a scriptable C++ lib purpose-built for generating non-overlapping bake/lightmap UVs; Blender ≥3.6 ships an xatlas-based packer, a [Blender-Xatlas add-on](https://blenderartists.org/t/blender-xatlas-v0-0-6-lightmap-unwrapping-and-packing/1239767) exists, and there's a [glTF-Transform + xatlas proof-of-concept](https://github.com/donmccurdy/glTF-Transform/discussions/792) for atlasing straight in the glTF domain ([xatlas](https://github.com/jpcy/xatlas)). **UVPackmaster 3** ($44 single-user) only if packing efficiency becomes a real bottleneck ([CG Channel](https://www.cgchannel.com/2025/08/uvpackmaster-3-4-for-blender-adds-one-click-uv-repacking/)).
- **Bake:** headless Cycles bakes of Diffuse/Normal/AO/Roughness per object; for the static museum shell, additionally bake a **lightmap on UV2** (soft museum lighting + contact shadows), applied via `lightMap` in three.js. Good non-artist walkthroughs: [Svilenković "How to Bake Lighting for Web"](https://svilenkovic.com/3d/how-to-bake-lighting-for-web), [tchayen "Baked lighting in r3f"](https://tchayen.github.io/posts/baked-lighting-in-r3f), [three.js forum batch-bake thread](https://discourse.threejs.org/t/made-a-blender-script-for-batch-baking-lightmaps-to-optimize-models-for-threejs/82346). Fully agent-automatable once the scene file is set.

### Phase 5 — Delivery (fully agent-automatable, belongs in the build)

- **Channel-pack ORM** (AO→R, Roughness→G, Metallic→B — the glTF-native layout; three.js `MeshStandardMaterial` reads occlusionTexture/metallicRoughnessTexture from one image).
- **Compress with glTF-Transform CLI**: `gltf-transform etc1s` for albedo/ORM, `uastc` for normal maps (normals fall apart under ETC1S), e.g. `gltf-transform uastc in.glb out.glb --slots "{normalTexture}" --level 4 --rdo` then `etc1s` for the rest; three.js side is `KTX2Loader` + `gltfLoader.setKTX2Loader(...)`, transcoding to BC7/ASTC/ETC per device ([gltf-transform.dev](https://gltf-transform.dev/), [three.js forum guide](https://discourse.threejs.org/t/compressing-a-gltf-textures-with-ktx2/40638)). KTX2 stays compressed *in GPU memory* — this is what makes 15 models + environment fit mobile.
- **Budgets** (Khronos 3D Commerce Real-time Asset Creation Guidelines, v2.0 refreshed at SIGGRAPH 2025): per-asset ideally <5 MB, ≤100k tris, textures 1K for BaseColor/ORM/Emissive and 2K for normals, minimum material count per asset ([guidelines](https://github.com/mlimper/3DC-Asset-Creation/blob/main/asset-creation-guidelines/RealtimeAssetCreationGuidelines.md), [2.0 announcement](https://www.khronos.org/blog/introducing-asset-creation-guidelines-2.0-siggraph-2025)). For this gallery: 1K×3 maps per computer model, 2K tiled sets shared across the environment, one 2K–4K lightmap atlas, one ≤2K HDRI (or prefiltered PMREM) — roughly 60–100 MB GPU on desktop, halve resolutions for mobile via a second KTX2 set or capped `renderer` texture size.

## Material recipes for the key surfaces

**Aged beige/yellowed ABS plastic** (`MeshPhysicalMaterial`): baseColor from Midjourney/library beige with *non-uniform* yellowing — the photochemical yellowing of ABS is strongest where light hit, so drive a beige→amber gradient by a baked AO-inverse or top-down mask; roughness ~0.45–0.6 base (plastics cluster near mid-roughness; dust/age adds +0.2–0.35 [per this roughness guide](https://sameerbaloch.com/roughness-setting/)), with a fingerprint/smudge mask lowering roughness to ~0.3 in touched areas (around keyboards, drive bays); metalness 0; a **subtle clearcoat (0.1–0.25, clearcoatRoughness 0.3–0.4)** sells slightly-glossy injection-molded shells better than SSS (SSS is unnecessary — ABS is opaque; save the cost); fine pebble/spark texture as a high-frequency normal detail. No env map = dead plastic; the HDRI from Phase 1 is mandatory.

**CRT glass:** build the screen as two layers — (1) curved glass shell: `MeshPhysicalMaterial`, near-black baseColor, roughness 0.05–0.15, high envMapIntensity, optional clearcoat 1.0 — the room HDRI reflection on the curve is the entire effect; (2) inset emissive screen mesh: `emissiveMap` carrying the screen content (your streamed station texture!), with the CRT treatment (scanlines, phosphor triads, barrel distortion, vignette) done in a small shader patch on the emissive term of a `MeshStandardMaterial` so specular glass highlights still layer on top — exactly the architecture of [unframework/threejs-crt-shader](https://github.com/unframework/threejs-crt-shader) (and its Konva fork), with parameter reference in this [interactive Three.js CRT demo](https://daenavan.github.io/crt-threejs/). Given the app already streams live OS video onto stations, this is a natural, high-payoff upgrade.

**Brushed metal shelves:** library brushed-steel set (ambientCG has several); metalness 1.0, roughness ~0.3–0.45 with the brushing direction in the normal map; true anisotropy is available via `MeshPhysicalMaterial.anisotropy` in recent three.js if the brushing needs to read at glancing angles; metal without an env map renders black — HDRI again mandatory.

**Museum floor (polished concrete or parquet):** CC0 tiled set + the drei **`MeshReflectorMaterial`** — purpose-built blurred planar floor reflection that respects roughness, extends `MeshStandardMaterial`, tunable `resolution` (256–512 is plenty), `blur`, `mixStrength` ([drei docs](https://drei.docs.pmnd.rs/shaders/mesh-reflector-material)). Prefer it over SSR postprocessing: SSR ([0beqz/screen-space-reflections](https://github.com/0beqz/screen-space-reflections), effectively in maintenance) suffers occlusion artifacts and mobile cost, whereas one planar reflector for one flat floor is the textbook case ([three.js forum discussion](https://discourse.threejs.org/t/screen-space-reflection-compatible-postprocessing-solution-for-react-three-fiber/90244)). Subtle is convincing: mixStrength low, blur high, plus the baked lightmap for grounding.

**Badges/labels/keycap legends:** don't fight tiling — use small decal planes or a dedicated non-tiled "details" texture per model; Midjourney (no `--tile`) or plain SVG→PNG renders work; slight roughness/normal offset vs. the shell makes them read as separate parts.

**Bottom line:** the highest-leverage sequence is (1) HDRI environment + CC0 materials via scripted API pulls — instant, free, fully automatable; (2) a headless Blender+bpy pipeline (procedural aged-plastic node material → bake → glTF) as the reusable per-model factory; (3) Midjourney`--tile`+DeepBump for bespoke albedos; (4) glTF-Transform KTX2+ORM in the build. Paid tools are optional accelerators (Sampler for extraction quality, Painter for 2–3 hero models); the dead pool (withpoly, Ponzu, Mixer, post-2024 free Megascans) should be scrubbed from any plans.
