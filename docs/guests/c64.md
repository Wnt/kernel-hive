## CURSOR FIX (2026-07-16) — ✅ browser coordinates track; GEOS icon click certified

- **Root cause was three layers, not one:** VICE had no `Mouse=1` grab and left
  control port 1 at its default joystick; GEOS booted its built-in `JOYSTICK`
  input driver even though `COMM 1351` was on the disk; and QEMU's absolute
  tablet/VMware VMMouse handler absorbed REL events before VICE's SDL-relative
  mouse path could receive them.
- **VICE/GEOS fix:** launch with `-mouse -controlport1device 1351`, and boot an
  overlay-local `GEOS-1351.D64` whose `JOYSTICK` file is removed. `COMM 1351`
  is then the only disk input driver and becomes active when deskTop starts.
- **Bridge mapping:** browser positions remain absolute. `SH_POINTER=rel`
  converts each absolute browser sample into a bounded PS/2 delta; QEMU is
  tablet-free and uses `-machine pc-i440fx-11.0,vmport=off`, so the delta reaches
  Linux's generic PS/2 mouse, SDL relative mode, VICE's 1351 POT emulation, and
  finally the GEOS cursor. This is absolute target tracking at the browser/GEOS
  level, with relative transport at VICE's host-mouse boundary.
- **Clone proof:** `/data/vms/soltest/c64-geos-cursor-codex/proof/` contains
  `browser-ps2-a.png`, `browser-ps2-b.png`, `browser-ps2-icon-hover.png`, and
  `browser-ps2-icon-click.png`. Real SPA `page.mouse` positions at approximately
  30%/34%, 70%/66%, and 51%/39% put the GEOS arrow at the corresponding points;
  the final click visibly selects the `CONFIGURE` icon.
- **Live proof after promotion:** `/data/vms/streamhost/tiles/c64/proof/` contains
  `live-cursor-a.png`, `live-cursor-b.png`, `live-preference-click.png`, and
  `live-after-restore-{a,b}.png`. The first pair tracks two browser targets, the
  click frame visibly selects `MPS-803`, and the final pair proves movement again
  after an explicit `labctl reset c64` / `loadvm golden`.
- **Rollback:** the pre-fix qcow2 (internal `golden` dated 2026-07-15 10:55:58),
  launcher, and tile.env are in
  `/data/vms/streamhost/backups/c64-geos-cursor-20260715T235119Z/`. Restore with
  `systemctl stop streamhost@c64`, copy those three files back to
  `/data/vms/streamhost/tiles/c64/`, then `systemctl start streamhost@c64` and
  `labctl gen`.

## THE HARD-WON RECIPE (all non-obvious, all baked into the scripts)

### Base image (bridge-base.sh)
1. **The genericcloud `cloud` kernel has NO e1000 driver AND no bochs-drm.** The tile
   device set uses an e1000 NIC (→ no guest network/ssh) and `-vga std` (→ X errors
   "no screens found"). Fix: install `linux-image-amd64` (generic) AND **purge the
   cloud kernel** so grub boots the generic one (has e1000 + bochs-drm → `/dev/dri`).
2. **SLIRP DHCP was unreliable** (networkd-wait-online hung, no lease). Use a
   **deterministic STATIC IP** = SLIRP's fixed addressing (`10.0.2.15/24`,
   gw `10.0.2.2`, dns `10.0.2.3`) + mask `systemd-networkd-wait-online`.
3. **VICE is NOT in Debian** (removed over ROM/DFSG licensing) — built from source
   (SDL2). `./configure` aborts without `libcurl4-openssl-dev`. Also **`make install`
   SKIPS the C64 BASIC ROM** (`basic-901226-01.bin`) → x64sc SEGFAULTS with no
   output → copy the full `data/C64` ROM set into the install dir.

### Kiosk / VICE launch (c64.sh → /etc/bridge/launch.sh)
The verified launcher (WHY each flag — VICE 3.9 SDL2):
```
export XDG_RUNTIME_DIR=/run/user/$(id -u)
export SDL_RENDER_DRIVER=software    # GPU-less host: software SDL renderer, no GL
export SDL_VIDEODRIVER=x11
exec x64sc -mouse -controlport1device 1351 \
  -sounddev alsa -drive8truedrive -autostart-handle-tde -VICIIdsize \
  -autostart /opt/bridge/media/GEOS-1351.D64
```
- **`-drive8truedrive`** — TRUE DRIVE emulation on drive 8. **REQUIRED or the GEOS
  deskTop hangs.** There is NO global `-truedrive` in 3.9 (it is per-drive).
- **`-autostart-handle-tde`** — keep true-drive ON during autostart (else GEOS
  breaks: the loader and the running deskTop both need the real 1541).
- **`-mouse -controlport1device 1351`** — set VICE `Mouse=1` and attach the
  proportional 1351 model to C64 control port 1. Without both, SDL events never
  reach a 1351 device.
- **`GEOS-1351.D64`** — overlay-local copy of `GEOS.D64` with the `JOYSTICK`
  input-driver file removed by `c1541`; the existing `COMM 1351` driver is then
  selected on boot.
- **`-VICIIdsize`** — double-size **WINDOW** (~768×544) centred on the black bare-X
  root. Do **NOT** use `-VICIIfull`: SDL real-fullscreen mode-switch renders **BLACK**
  in the captured std-VGA framebuffer. A window captures correctly.
- **`-sdl2` and `-fullscreen` are INVALID flags** (silent-ish failure → kiosk loop).
- **`-sounddev alsa`** → ALSA default → AC97. The AC97 card (device set) MUST be
  present, else VICE pops a MODAL "Sound: initialization failed for device 'alsa'"
  dialog and BLOCKS (the earlier "black screen" mystery was this modal, in a boot
  that lacked the sound card).
- **x64sc SEGFAULTS in its early logger when stdout is NOT a terminal** (strlen(NULL)
  in `resources_set_defaults`→`log_message`). So launch.sh must **NOT** redirect
  stdout to a file — the kiosk runs it on **tty1 (a terminal)**, which is fine.
- Kiosk = getty autologin `bridge` on tty1 → `startx` → `~/.xinitrc` (xset s off,
  1024×768) → `/etc/bridge/launch.sh`. If a bad launcher looped getty into
  `start-limit-hit`, clear it with `systemctl reset-failed getty@tty1` before restart.

```
qemu-system-x86_64 -name streamhost-c64 -enable-kvm -machine pc-i440fx-11.0,vmport=off -m 1536 -smp 2 -cpu host -rtc base=localtime \
  -drive file=overlay.qcow2,if=ide,format=qcow2 -boot c \
  -vga std \
  -display dbus,p2p=on,audiodev=snd0 \
  -audiodev dbus,id=snd0,out.frequency=48000,out.channels=2,out.format=s16 -device AC97,audiodev=snd0 \
  -usb \
  -netdev user,id=n0,hostfwd=tcp:127.0.0.1:5814-:22 -device e1000,netdev=n0 \
  -loadvm golden   # when the snapshot is present
  -qmp unix:qmp.sock,server=on,wait=off -pidfile qemu.pid
```

## Deviations / caveats
- **LinApple (Apple //e) did NOT build** in the base (needs ImageMagick `convert`
  for its PNG→XPM step AND fails a `Video.o` compile under modern g++). Non-critical
  (off the C64 acceptance path). The Apple II fan-out should fall back to
  `mame apple2e` (apt) or a fixed LinApple. VICE/hatari/cap32 all built.
  *(Resolved: the build was fixed and **LinApple IS the live `apple2` emulator**
  — see `docs/guests/apple2.md`; no mame fallback was needed.)*
- **Pointer:** `SH_POINTER=rel`, no tablet, and `vmport=off`. The SPA still emits
  absolute video coordinates; streamhost translates them to bounded/paced PS/2
  deltas because VICE 3.9 SDL2 consumes relative mouse motion. This mapping is
  cursor/icon-click certified through the real browser path.
- **Windowed, not true-fullscreen:** the GEOS window is ~768×544 centred on a black
  1024×768 root (real SDL fullscreen renders black in capture). Cosmetic; the
  deskTop is fully visible and captured. A future option is to match the X screen
  resolution to the VICE window for edge-to-edge fill.
