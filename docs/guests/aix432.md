# aix432 guest — IBM AIX 4.3.3 with CDE (RS/6000 7020 "40p", PowerPC/PReP)

Status: **CANDIDATE — not on the floor, not in any lineup.** The registry entry
is `enabled: false` / `lifecycle: candidate`; slot **201** / UDP **54201** and
retronet **10.99.0.28** are claimed, nothing is deployed. The desktop, the
browser and the game all render on the emulated card; what is missing is a
tracked launcher, a restore-proven golden, and a relay-reachable port (see
[Promotion](#what-still-gates-promotion)).

Research note — **read it before touching anything here**:
[`docs/lab/research/candidate-aix.md`](../lab/research/candidate-aix.md). It is
the source of truth for what this machine is and what is honest to claim about
it. This page is the operator's summary of it.

## Identity and source

- Public ID / station directory: `aix432`
- Archetype: `beige-tower-crt`
- Target: **AIX 4.3.3 with X11R6 / Motif 2.1 / CDE**, on `qemu-system-ppc -M 40p`
  (IBM RS/6000 7020 model 40P), rendering **natively into an emulated
  framebuffer** — no remote X, no XDMCP. That constraint is the whole exhibit:
  the Virtual OS Museum's "graphical AIX" is an Xephyr XDMCP session with
  host-supplied fonts, which this lab has ruled out.
- **It is 4.3.3, not the originally scoped 4.3.2, and that is deliberate.**
  AIX 4.3.2's installer kernel stops driving the emulated LSI 53c810 after one
  retry cycle and hangs at 100 % CPU forever; 4.3.3 streams ~1100 reads and
  installs fine. Same firmware, same media layout, same patches — measured, not
  assumed (research §1). The **4.3.2 Bonus Pack** is installed on top, which is
  where Ultimedia Services and Netscape come from.
- Media: see [`ASSETS-MANIFEST.md`](../lab/ASSETS-MANIFEST.md) — AIX 4.3.3
  Volumes 1-4 (volume 1 is the only bootable one; it carries the type-0x41 PReP
  boot partition), the 4.3.2 install set and Bonus Pack CD1+CD2, the GXT130P
  support software, CorelDRAW 3.5 for UNIX, IBM's own AIX game binaries, and the
  firmware ROMs. **Preservation class throughout**: IBM commercial software with
  no redistribution grant. Private exhibit only — never committed, never served.

Three things live only on the `aix432-s3` branch, and the station does not work
without any of them:

1. **Hervé Poussineau's S3 Trio card** (2017, never merged upstream), forward-
   ported to 11.0.2. It gives *Open Firmware* a framebuffer instead of the
   serial console every published AIX-on-QEMU recipe uses. **AIX itself can
   never bind to it** — AIX 4.3 has no S3 driver of any kind (research §4).
2. **`hw/display/mga.c`**, new — the Matrox behind the GXT130P, which is what
   AIX *can* bind to, including the 2D engine the DDX actually uses (ILOAD
   colour-expansion, BITBLT, LINE/AUTOLINE, TRAP, per-op clipping).
3. **Artyom Tarasenko's AIX fixes** (53c810 register hiding, raven PCI I/O
   decoding, lsi reentrancy) plus **a PS/2 fix**: AIX's `kbddd` programs scancode
   set 3 per-key make/break with `0xFC` followed by a *list* of key numbers, and
   QEMU ACKed only the first and RESENT the rest — which failed the keyboard
   watchdog, failed `lftKiInit`, and made **every `/dev/lft0` open fail**.

## The firmware is the exhibit

The single most surprising fact about this station: **the graphics stack comes
up because of the boot ROM, not because of the display model.**

AIX drives graphics through `gxme0` (Graphics Data Transfer Assist) → `rcm0` →
the `aixgsc` syscall gateway → the adapter DDX. `cfggxme_rspc` configures
`gxme0` by enumerating **PReP residual-data device packets**, and Open Firmware
builds that structure itself. Under Tarasenko's OF, `gxme0` and `rcm0` stay
`Defined`, `aixgsc` never registers, the DDX dies, and X does not start — with
the display model completely innocent (zero MGA registers touched).

Under the **genuine IBM ROM**, the authentic residual data brings up `gxme0`,
`rcm0`, `mg21`, `lft0` **and `paud0`** with **no guest patching at all** —
`rcm_load` `cmp`-verifies pristine — and CDE renders. Two changes make that ROM
boot:

- **`PREP_TB_FREQ=15000000`** — a new environment override on the fork. The
  firmware assumes a 15 MHz timebase (66.67 ns/tick constants); QEMU offers
  100 MHz.
- **skip the single POST `settimeofday` call** (the `bl` at `0x74da8`). The real
  7020-40P shipped a **PowerPC 601**, whose RTCU/RTCL count {sec,nsec} natively;
  QEMU has no 601 model, so the firmware takes its **604 fallback path**, stores
  the clock offset as negated packed {sec,nsec} and adds it back **as ticks** —
  then asserts *"time went negative"* and spins in an LED-flash loop at
  `0x358c0` displaying crash code **888-102-700-0A5** on an operator panel QEMU
  does not have. That is what a "frozen splash at 50 % CPU and no serial output"
  actually was.

**The skip is currently a GDB-RSP helper, and that is debt**: it should become a
QEMU-side option rather than a gdbstub babysitter. Seeding NVRAM with a valid
date/config is an untested alternative. A station that needs a debugger attached
to boot is not a station that can be brought up by `systemctl`.

## Traps, in the order they bite

1. **`-M 40p` has no IDE.** `block_default_type` is `IF_SCSI`, so `-hda` and
   `-cdrom` both land on the LSI. The ROM's `/pci/ide/...` devaliases are stale
   and `dev /pci ls` shows no IDE node at all.
2. **Autoboot never works.** OF tries `/pci/ethernet` and gives up. Interrupt it
   with a few CRs and boot explicitly: `boot cdrom:2` to install, `boot disk`
   afterwards.
3. **RAM is capped.** `-m 512` is refused outright ("try 192 MB"); OF reports
   128 MiB whatever you pass, matching `default_ram_size`.
4. **Do not move the SCSI controller.** AIX's bootstrap has `pci1000,1@c,0`
   baked into its strings, which makes slot 12 look right. It is not: OF
   enumerates a fixed set of slots and moving the LSI to 12 makes it vanish from
   the device tree entirely. 4.3.3 boots fine from slot 1.
5. **Audio needs `-global cs4231a.dma=6`.** AIX's CS4231 driver fixes play DMA
   at 6; QEMU defaults to 3. iobase and IRQ already match.
6. **Two red herrings, both already chased.** `invalid/unsupported opcode:
   00 00 00 00 @ 07ea6390` in the QEMU log appears on the *successful* 4.3.3
   boot too. And the SCSI BARs reading back unmapped at the `ok` prompt is
   normal — OF clears them during its own PCI probe, and pre-assigning them from
   `ibm_40p_init` does not help. Both patches were tried and reverted; **do not
   re-derive them.**

## What runs, and what does not

Screendump-verified on the emulated card (research §4.5):

| | |
|---|---|
| CDE — dtgreet, dtwm, dtsession, dtfile | full desktop: text, icons, menus, front panel |
| `aixterm`, `xclock` | live prompt, clean draw and erase |
| **Netscape Communicator 4.08** | fully rendered — toolbar icons, logos, text |
| **Quake 1.07** (IBM's own AIX build) | renders and plays its demo loop. Needs `LIBPATH=/usr/lpp/som/lib:/usr/lib` (it links `som.dll` and `UMSobj.dll`). The olive tint is period-correct colormap flashing on the 8-bit PseudoColor visual, not a defect. |
| Abuse | loads and runs, its `aix_sdrv` holds `/dev/paud0` — **but the window stays black** |
| CorelDRAW 3.5 | **will not launch.** Its `libwix_sh.a` imports from the AIX **3.2**-era `libX11.a(shr.o)`; every libX11 on 4.3.3, R4/R5 compat trees included, has only `shr4.o`. Renaming gets as far as `Symbol readv (number 345) is not exported`. A shim needs a C compiler, and AIX's is a separately licensed product that is not installed. **Recorded as a dead end — do not re-derive it.** |
| Hardware cursor | **not implemented** — the pointer is invisible |

Audio is proven at the device level only: `paud0` is `Available`, `/dev/paud0`
is held open by real applications with real CPU time against it. **The waveform
has never been captured** (`-audiodev wav,...` costs a full reboot), and there
is **no boot chime** — the firmware never drives the codec.

Remaining device-model gaps, all small: the hardware cursor, strict
`CXRIGHT==0` clip semantics (stale spokes when a window maps), ILOAD BFCOL at
8bpp only, and TRAP pattern fills drawn solid.

## How to rebuild

Builder: [`scripts/build-guests/tiles/aix432.sh`](../../scripts/build-guests/tiles/aix432.sh)
— `--qemu` (clone + build the fork), `--firmware`, `--media`, `--disk`, then
`--install`, which **deliberately refuses to run**: the BOS installer is a
curses TUI over the serial line. The interactive recipe it was performed with is
recorded in the script's own comment block, step by step, so the next run can be
scripted *against* it rather than rediscovering it.

Disk images under `/data/vms/sandbox/aix432/base/`, each a checkpoint of the
one before it:

- `aix433-base.qcow2` — bare AIX 4.3.3, boots to `Console login:`
- `aix433-x11-ums-games.qcow2` — plus X11/CDE, Ultimedia Services, Quake, Abuse
- `aix433-full.qcow2` — plus CorelDRAW 3.5

Two things the BOS install does not do for you: a **1 GB `/apps` JFS** has to be
created, and **`/usr` has to be grown** — a default install leaves it with about
25 MB free, which is not enough for X11 let alone the Bonus Pack.

## Networking

Retronet **web plane only**, and not yet joined:
[`docs/lab/retronet/STATION-aix432.md`](../lab/retronet/STATION-aix432.md).
There is no ICQ client for AIX 4.3/PowerPC here, so no `icq` plane and no
roster persona. There is **no network exec channel** and there will not be one:
the guest has no route off the bridge.

## Golden, input, and rollback

- Reset mode: `loadvm golden` — declared in the registry, **not yet baked**. The
  golden is being captured by a parallel bring-up; a checkpoint, its binary and
  its device set are ONE combination, so it is only trustworthy once the tracked
  launcher exists and the NIC question is settled.
- Pointer/click/drag/wheel/keyboard: **unproven** (`reset.mouse` and
  `reset.keyboard` are `UNVERIFIED` on purpose). The keyboard path is known to
  work at the driver level — that is what the PS/2 set-3 fix bought — but
  nothing has been proven through the daemon.
- Cold boot: **not audited.** `scripts/coldboot/aix432-bootrec-arm.sh` is still
  the scaffold's draft case arm with a `TODO` disk list; no boot clip.
- Credentials reference only, never values: `guest/aix432`.
- Rollback: nothing is deployed, so the rollback is deleting the sandbox disks.
  The install is reproducible from the recipe above, at the cost of the ~60 min
  TCG BOS install plus the fork build.

## What still gates promotion

1. **A tracked launcher.** `streamhost/stations/aix432/` does not exist. Until
   it does, `runtime.qemu.launcher` / `envFixture` / `emitArgs` / `auxFiles` are
   deliberately absent from the registry entry rather than pointing at files
   nobody has written, and `launcherParity.status` is `unwritten`.
2. **A restore-proven golden**, baked against that launcher's pinned device set
   — with the NIC decided first.
3. **A public-relay-reachable port.** UDP **54201 is outside**
   `ports.publicRelayLow..High` (54080-54200) in
   [`registry/registry-v1.json`](../../registry/registry-v1.json). Promoting the
   entry to `production` as it stands **fails validation**, and shipping it past
   that check would put an exhibit on the floor that streams perfectly on the
   LAN and is unreachable through the edge. Slot 201 was chosen because slots
   **152-200 are reserved for the walk-in clone pool**
   ([`WALKIN-BRIEF.md`](../lab/WALKIN-BRIEF.md)) — the scaffolder's allocator
   does not know about that reservation. Either widen the relay window (edge
   nftables, the `wg0.conf` comment, `docs/PUBLIC-GALLERY.md` and
   `publicRelayHigh` together) or take a slot inside it.
4. **A pointer decision**, which realistically means implementing the MGA
   hardware cursor: an exhibit whose pointer is invisible is not one a visitor
   can use.
5. The usual lineup work the playbook lists for any new station — poster prose
   and hero image, `spa/src/scene/machines.ts` + `machineIdentity.ts` +
   `keyboardProfiles.ts` — and **three** runtime documents published, not two.
   The third is `golden-manifest.json`, whose keys are the allow-list for
   `POST /restore/<id>`: miss it and the tile looks perfectly healthy while its
   "reset to golden" button returns `404 unknown osId`. It is no longer a file
   anyone maintains by hand — it is **rendered from this registry entry**
   (production `id` + `reset`, ordered by `render.goldenOrder`) and published to
   `/data/vms/streamhost/serve/golden-manifest.json`, so the trap now reduces to
   remembering to publish after regenerating. `tiles.json` and
   `gallery-manifest.json` are the other two.
