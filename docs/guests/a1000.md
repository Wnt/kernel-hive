# Amiga 1000 — the first Amiga

Status: **LIVE on the box, host-native (no X)** since 2026-09-09 ~19:57 —
streamhost@a1000 on udp/54188, floppy-boot Workbench 1.2 desktop and pointer
both proven through the real daemon. `enabled: true` in the registry but not
yet given a `listing` block for the grid; promote by reviewing `/os/a1000`
and dropping one in.

**Guest:** an emulated **Commodore Amiga 1000** (Motorola 68000 @ 7.16 MHz,
OCS chipset — Agnus/Denise/Paula, 512 KB chip RAM) booting **Workbench 1.2**
(1986) from floppy — the machine as it shipped: the A1000 has no Kickstart in
ROM, only a WCS (write-control store) that a boot ROM loads from a Kickstart
disk on every power-up. **HOST-NATIVE, no X** per rule 13: **FS-UAE 3.2.35
(the station's own pinned source build, `kernel-hive/integrated` fork)
runs directly on labhost with no Xvfb** — the shared launcher
`streamhost/stations/fsuae-native/x11-runtime.sh`, `SH_CAPTURE=shm` at
640x512, `SH_INPUT_BACKEND=mamesock` (the IFB1 shm publisher +
`FSUAE_NATIVE_CTL_SOCK` control socket, same plane as the MAME/VICE
stations), `SH_AUDIO_SOURCE=fifo`. The pinned Xvfb `:88` display this
station used to render into is released and unused; `runtime.x11.display`
stays in the registry as inert bookkeeping.

> Distinct from `amiga` (A500 / Workbench 1.3 **bridge kiosk**, not
> host-native) and `amigaos35` (A4000/040, AGA, OS 3.5 — the end of the
> classic 68k line). This is the beginning of it: the 1985 machine with the
> designers' signatures moulded inside the case.

## Emulator decision

FS-UAE — the shape sibling of `amigaos35`, converted to the host-native
plane (rule 13, `docs/lab/FSUAE-NATIVE-BRIEF.md`): `--mouse_integration=1`
is mandatory on the launch line (mousehack never registers without it); the
retronet cage is NOT copied — a 1986 guest predates the web and ships with
no network plane. Built as the station's OWN pinned copy (`FSUAE_STATION=a1000
build-fsuae-native.sh` → `assets/a1000/fsuae-native/`, never shared with
`amigaos35`/`amix`), from the `kernel-hive/integrated` fork (headless entry +
shm publisher + mamectl socket + FIFO audio, submodule
`third_party/fs-uae-kernel-hive`).

- `--amiga_model=A1000` (OCS, 68000, 512 KB chip — FS-UAE routes this to
  `chipset_compatible A1000` / `cs_a1000ram` in `config-model.c`).
- Window / X screen: 720x568 (`xwininfo`, same as `amigaos35`; a PAL
  640x256 Workbench 1.2 desktop renders inside it).

## Pinned machine (acceptance)

- `fs-uae 3.2.35` (pinned source build, patched), A1000 model, 512 KB chip
  RAM, OCS.
- Storage: no HDF. DF0 = Workbench 1.2 rev 33.56 (Disk 1), DF1 = Extras 1.2
  (GB, Disk 2) — both fresh work copies of the golden ADFs, reflinked on
  every launch.
- ROM slot: the 262 144 B Kickstart 1.2 r33.180 image (the proven route —
  see Open items for the authentic path).
- Display: headless, no X — shm publish at 640x512 (daemon log
  `[shmcap] geometry 640x480 -> 640x512`), `SH_CAPTURE=shm`.
- Input: `SH_INPUT_BACKEND=mamesock` against `FSUAE_NATIVE_CTL_SOCK`
  (HELLO `screen=WxH`, MOVEA in published-frame pixels, DOWNn/UPn, `KEY 0|1
  amiga <raw>` via `amiga.keymap`, 97 rows derived from the Hardware
  Reference Manual — keys not yet measured end to end); `--mouse_integration=1`
  is mandatory on the launch line. `SH_BTN_MIN_HOLD_MS=150` (FS-UAE's
  mousehack never samples an instant press; proven with a 200 ms gap
  between double-click presses).
- Audio: off (`SH_AUDIO=off`).
- Networking: none — pre-web guest, no retronet plane at all.

## Ready scene / golden

- Ready state: Workbench 1.2 desktop (blue, 640x256 PAL in the 720x568
  window) — RAM Disk + "A500 WB 1.2" + Extras disk icons on the right,
  title bar "Workbench release 1.2.  364736 free memory", no windows open.
- Reset mode: `relaunch`, `FSUAE_NATIVE_CHECKPOINT=0` — **no statefile**.
  Every launch is a deterministic cold boot from fresh copies of the
  Workbench and Extras ADFs. Measured at ~55 s to the desktop, both with
  `amigaos35`'s binary (before the station's own was staged) and again with
  the station's own build (confirmed via `/proc/<pid>/exe`) — identical
  desktop up by +55 s both times; golden + binary + device set is the
  proven combination.
- **Bake note:** unlike `amigaos35`'s FFS-root HDF trap, there is no disk
  image to keep clean here — DF0/DF1 are re-copied from the golden ADFs on
  every boot, so there is nothing to "dirty" between resets.

## Input proof

- **Pointer PASS through the real daemon.** Proven exact on an A3000 rig
  (the shared plane): MOVEA 41,148 landed the tip at 38,148; a double-click
  opened the System window. An instant press+release is never sampled by
  FS-UAE's mousehack poll — `SH_BTN_MIN_HOLD_MS=150` hold, 200 ms between
  double-click presses, both proven.
- **Reset PASS.** Reset = relaunch; the daemon lines
  `[shmcap] geometry 640x480 -> 640x512`, `[mamesock] connected, HELLO
  verified`, `[audio] fifo open` confirm the plane comes up clean each
  time.
- **Keyboard UNVERIFIED end to end.** `amiga.keymap` (XT scancode → Amiga
  raw) is built from the Hardware Reference Manual but not yet measured
  through a real typed session; `labctl type` is now possible with the
  multi-client socket, so this is the next runner, not a known-bad result.
- fs-uae headless with the daemon attached measures 80% of one core;
  publish rate 50 fps.

## Open items

- **Authentic Kickstart-from-floppy bootstrap does not boot in this build.**
  The real A1000 has no Kickstart ROM — a 64 KB (or 8 KB ALTROM) boot ROM in
  the ROM slot loads Kickstart from a floppy in DF0 into the WCS. Every
  combination tried (full 65536 B dump, the 8192 B ALTROM slice, a
  131072 B doubled dump to close the FS-UAE `read_kickstart` FIXME gap, and
  swapping in the A1000-specific r33.166 Kickstart) reset-loops: the
  framebuffer stays flat grey and `fs-uae.log` shows the checksum
  alternating between two states in a steady 1:2 rhythm — the WCS write
  latch (`a1000_handle_kickstart`, `src/memory.cpp`) is firing, so the
  bootstrap does read the Kickstart disk and hand over, but whatever lands
  in the WCS never executes; the machine hard-resets and repeats forever.
  Full trace: `/data/vms/sandbox/a1000/smoke/BOOTSTRAP-FINDINGS.md`. Next
  two theories, in priority order:
  1. Dump `kickmem_bank.baseaddr[0..0x40000]` after the first WCS write and
     diff it against the raw r33.180 file — if the bytes differ, the
     ADF_KICK disk-synthesis offset in `disk.cpp` (`tid->offs =
     i*512*num_secs - 512`) is delivering the image shifted by the "KICK"
     sector header, and the bootstrap is executing garbage.
  2. The 1:2 rhythm suggests a *soft* reset is also re-triggering
     `a1000_reset()` (`devices.cpp:71` calls it unconditionally); patch it
     to fire only on a hard reset in a sandbox build and re-run the race rig.
  The launcher already carries the switch
  (`FSUAE_NATIVE_A1000_BOOTSTRAP=1`, default `0`) for whichever theory
  lands — flipping it is a launcher change, not a re-bake, since reset is
  already a cold relaunch.
- **Keyboard is unverified end to end** (see Input proof) — a runner needs
  to reach a Shell/CLI and type through the daemon's real path, not just
  XTEST-direct-to-window.
- Not yet promoted to the visible grid — pending the operator's eyeball at
  `/os/a1000` and a `listing` block.
