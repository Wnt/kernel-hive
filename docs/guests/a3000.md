# Amiga 3000 (Workbench 2.04) — gallery station notes

Status: **LIVE on the box, host-native (no X)** since 2026-09-09 ~19:57 —
the golden HDF compose recipe landed on `a3000-build`, and pointer proof is
through the real daemon: MOVEA 41,148 landed the tip at 38,148, double-click
opened the System window. Not yet in the lineup / tile grid.

**Guest:** an emulated **Commodore Amiga 3000** (Motorola 68030 + 68882 FPU,
ECS chipset, Kickstart 2.04 r37.175 A3000 ROM) booting straight to the
**Workbench 2.04** desktop from a host-composed FFS hard-disk image. No
retronet plane — this is a pre-web (1991) guest. **HOST-NATIVE, no X** per
rule 13: **FS-UAE 3.2.35, the station's own pinned source build**
(`assets/a3000/fsuae-native/`, `kernel-hive/integrated` fork; bootstrap on
labhost, configure/make in CT950 because labhost lacks `zip`), publishing
via the shared launcher `streamhost/stations/fsuae-native/x11-runtime.sh` —
`SH_CAPTURE=shm` at 640x512, `SH_INPUT_BACKEND=mamesock` against the
`FSUAE_NATIVE_CTL_SOCK` control socket, `SH_AUDIO_SOURCE=fifo`. The pinned
Xvfb `:89` this station used to render into is released and unused.

> Distinct from `amiga` (A500 / Workbench 1.3, bridge kiosk) and `amigaos35`
> (A4000/040 / Workbench 3.5, host-native). `amix` runs Amiga UNIX on this
> same A3000 hardware and the same Kickstart 2.04 A3000 ROM dump. Lineup order:
> `amiga` (1985/1.3) → **`a3000`** (1991/2.04) → `amigaos35` (1999/3.5), with
> `amix` alongside on the shared A3000 hardware.

## Emulator decision

FS-UAE — the same choice made for `amigaos35`, for the same reasons (proven
in-lab, `bsdsocket_library` for a future retronet join even though this guest
ships without one, `save_states`/`load_state`). Not re-surveyed for this
station: the 2026-08-24 survey in `docs/guests/amigaos35.md` stands. Shipped
as `FSUAE_STATION=a3000`'s own pinned 3.2.35 source build
(`build-fsuae-native.sh`) — a separate binary from `amigaos35`'s, not shared,
even though both carry the same lab mousehack-rearm patch.

## Pinned machine

- `fs-uae 3.2.35` (pinned source build, patched), `--amiga_model=A3000
  --chip_memory=2048 --fast_memory=8192` (68030 + 68882, ECS, 32-bit
  addressing). FS-UAE defaults the A3000 model to Kickstart 3.1 — this
  station passes the 2.04 A3000 ROM explicitly.
- Kickstart: 2.04 r37.175 (A3000), 524288 B, sha256 `563f948a…` (see above).
- Storage: `hard_drive_0` = FFS hardfile composed host-side from the four
  2.04 ADFs with amitools xdftool (Workbench disk as root, Extras and Fonts
  merged in, Install disk kept whole), the same technique `amigaos35`'s
  builder uses for its 3.1 set. No floppies, no statefile, no network in the
  shipped device set.
- Display: headless, no X — shm publish at 640x512 (`SH_CAPTURE=shm`).
- Input: `--mouse_integration=1` mandatory on the launch line (mousehack
  never registers without it); `SH_INPUT_BACKEND=mamesock` against
  `FSUAE_NATIVE_CTL_SOCK` (MOVEA in published-frame pixels, DOWNn/UPn, `KEY`),
  `SH_BTN_MIN_HOLD_MS=150` (instant press+release is never sampled by the
  mousehack poll; 200 ms between double-click presses proven).
- Audio: off (`SH_AUDIO=off`), same as `amigaos35`'s dark launch.
- Networking: none. This is a pre-web guest — no netns cage, no retronet
  plane.

## Ready scene / golden

- Target ready state: the Workbench 2.04 desktop (no first-run "KeyMap
  Selection" script — the smoke rig's floppy boot hits that prompt at ~60 s,
  but the HDF golden's startup-sequence must not carry it, per
  `A3000-WAVE.md`'s smoke-boot note).
- Golden file: `a3000-system.hdf`, composed host-side by the `build` stream
  from the four ADFs (never booted-then-captured — see the FFS `bm_flag`
  trap below).
- Reset mode: `relaunch` (deterministic cold boot from the golden HDF, no
  statefile), matching `amigaos35`'s decision and reasoning — UAE savestates
  were rejected there for nondeterministic restore behavior.
- Pointer proof: through the real daemon — MOVEA 41,148 landed the tip at
  38,148; a double-click opened the System window. Keyboard is unverified
  end to end (see `FSUAE-NATIVE-BRIEF.md`).
- **Bake trap inherited from `amigaos35`:** an FFS volume written by xdftool
  boots fine, but a golden captured from a RUNNING session has a dirty root
  `bm_flag` (FFS sets it only on flush/unmount) and OS 2.04's validator fails
  on it — compose the golden host-side, never boot-then-capture the golden
  file itself.
- The proof gate is the captured framebuffer through streamhost, never logs.
